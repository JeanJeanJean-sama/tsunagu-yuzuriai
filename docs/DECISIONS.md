# 決めたことの記録（DECISIONS）

新しい判断は一番下に追記してください。書き方：日付／決めたこと／理由／ほかの案。

---

### D-001 画面は GitHub Pages に置く（2026-10-05）
- **理由**：無料で、数十人規模なら容量・転送量とも十分。会のメンバーが GitHub 上で直せる。
- **ほかの案**：Netlify / Vercel（同等。必要になれば移行は容易）。

### D-002 ビルドなしの素の HTML/CSS/JS にする（2026-10-05）
- **理由**：Node.js などの環境がない人でも、ファイルを直してアップロードするだけで公開できる。数十人規模なら十分な速さ。
- **ほかの案**：React + Vite（画面が大きく複雑になったら検討。その場合は GitHub Actions で自動ビルド）。

### D-003 試作版は localStorage、本番は Supabase（2026-10-05）
- **理由**：まず画面と使い勝手を会で確かめたい。外部サービスの契約・設定なしで始められる。
  データ層を `store` に分けたので、画面を変えずに保存先だけ差し替えられる。
- **Supabase を第一候補にした理由**：表の形のデータ（投稿・相談・メッセージ）と相性がよい。権限ルール（RLS）を SQL で明確に書ける。東京リージョンがある。
- **ほかの案**：Firebase（Firestore）。同等の機能があり、使い慣れた人がいれば選んでもよい。

### D-004 お金のやり取りは扱わない（2026-10-05）
- **理由**：会の目的は助け合い。決済を扱うと規約・法令・運営の負担が大きくなる。郵送時の送料は当事者どうしで相談。

### D-005 医薬品は投稿対象外、医療消耗品は未開封・期限内のみ（2026-10-05・暫定）
- **理由**：医薬品・医療機器の個人間譲渡には法令上の注意点がある。安全側に倒しておく。
- **状態**：暫定。会で専門家に確認して確定させる（ROADMAP「会で決めること」）。

### D-006 個人を特定できる情報を入力させない（2026-10-05）
- **理由**：障害・医療ケアは非常に機微な情報。ニックネーム・おおまかな地域のみとし、住所などは受け渡しが決まった相手にだけ個別に伝える運用にする。
